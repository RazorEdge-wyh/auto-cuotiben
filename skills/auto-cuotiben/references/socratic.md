# 苏格拉底式小测

目的：确认「能讲出来」而不是「看懂了」。一次只问一题，等回答后再决定下一步。

## 出题原则

- 题目必须挂在这次事件上：引用具体文件、命令或输出。
- 3 道题各管一件事：
  1. **概念**：某个机制到底是怎么运作的（不是背定义，要说因果）。
  2. **迁移**：换一个场景，同样的原理会怎么表现。
  3. **判断**：AI 这次的做法，哪一步是对的，哪一步只是碰巧对。
- 每题只问一个点。不要在一句话里塞三个问题。

## 提问节奏

1. 先问概念题，用户回答后**不要立刻说对错**，先追问一句：
   - 「你为什么这么想？」
   - 「如果换成 X，还成立吗？」
2. 再问迁移题。答不上来就给一个小提示，不要直接给答案。
3. 最后问判断题。这题最容易暴露「只看了结果」。

## 打分（0-5）

| 分数 | 含义 | 调度影响 |
| --- | --- | --- |
| 0-2 | 基本忘了 / 只记得结论 | 明天重来 |
| 3 | 提示后能想起来 | 间隔 1 天 |
| 4 | 能独立讲对，个别细节含糊 | 间隔 3 天起，逐步拉长 |
| 5 | 能讲给外行听，还能指出边界 | 间隔按难度系数增长，21 天后可标「已掌握」 |

记录：

```bash
cuotiben grade <卡片ID> <0-5> --note "<卡在哪一步>"
```

## 用户答错时

1. 指出错在「把 A 当成了 B」，不要只说「不对」。
2. 回到讲义第 ④ 部分，让用户把实验亲手做一遍。
3. 再用一个更小的同类问题确认。
4. 如果还是不懂，把这条原理拆成两句人话，重新出题；不要重复同一道题。

## 用户答对时

追问一个边界问题：「什么情况下这个结论会不成立？」
能答出来才给 5 分。
