# 从「十分钟上线个人主页」看懂：浏览器到底怎么把文件变成页面

> 事件：你让 AI 做了一个个人主页，它写了 5 个文件、跑了构建命令、最后给了你一个能打开的网址。
> 黑盒指数 82/100（高）。这节课把它拆开。

## 1. 这件事你让 AI 做了什么

你的原话大意是：做一个能展示项目的个人主页，要好看，明天就要用。
AI 实际做了三件事：

1. 生成了 `index.html`、`style.css`、`main.js` 和一个 `assets/` 目录；
2. 执行 `npm create vite` 和 `npm run build`，把源码变成了 `dist/` 里的静态文件；
3. 把 `dist/` 推到一个静态托管服务上，给你一个 https 开头的网址。

你验收的方式是：打开网址，看到页面「挺好看」，然后关掉。
所以这节课要回答的是：从文件到页面，中间到底发生了什么。

## 2. AI 替你做的决定

1. **用 Vite 而不是一个纯 HTML 文件。** 纯 HTML 也能上线，但 AI 选了构建工具。代价是多了一层「源码 → 产物」，以后你改完源码必须重新 build，否则线上还是旧页面。
2. **用 flex 做一列卡片布局。** 这不是唯一解，grid 也能做。AI 选 flex 是因为它更常见、它对「一行一个卡片」的写法更熟。
3. **图片放 `assets/`、用相对路径引用。** 这样本地打开和线上部署都能找到图；如果写成绝对路径 `C:\Users\...`，线上一定裂图。
4. **部署到静态托管。** 这决定了你的页面没有后端：不能保存用户数据、不能藏 API key。

这四个决定，每一个都对应一个后面会考你的原理。

## 3. 底层原理拆解

### 3.1 浏览器把 HTML 变成 DOM，把 CSS 变成规则

浏览器拿到 `index.html` 后，不是直接「画出来」，而是先解析成一棵 DOM 树：每个标签是树上的一个节点。
CSS 文件被解析成一组「选择器 → 声明」的规则，浏览器把规则匹配到 DOM 节点上，算每个盒子的大小和位置，再画到屏幕上。

`style.css` 里的 `padding`、`border`、`margin` 之所以能让内容「挪位置」，是因为 CSS 盒模型规定：一个元素实际占的宽度 = content + padding + border + margin。
你看到的「好看」，是这四层尺寸被 AI 调对了，而不是页面本身有什么魔法。

### 3.2 源码 ≠ 浏览器实际执行的东西

你在编辑器里看的是 `main.js` 和 `style.css`，但浏览器拿到的是 `dist/` 里压缩过的文件。
`npm run build` 做的是：把模块依赖展开、把 CSS 提取合并、把变量名压短、把文件指纹写进文件名。
这解释了一个常见困惑：**为什么我改了源码，刷新页面却没变化？** 因为你改的是源码，托管的是上一版 `dist/`。

### 3.3 静态托管只是「按 URL 返回文件」

GitHub Pages、Vercel 这类静态托管，本质是一台 CDN：浏览器请求 `/style.css`，它就把这个文件原样返回，没有程序在服务器上运行。
所以它能做到「快」和「便宜」，但也决定了：任何需要保密的东西（API key）都不能放在前端，因为浏览器能下载到的文件，别人也能下载到。

## 4. 5 分钟亲手验证

打开你的主页，按 `F12` 打开开发者工具：

1. 在 **Elements** 面板里双击一段文字，改成「测试」，回车。页面上文字立刻变了，但刷新后又变回去。这说明 DOM 是浏览器内存里的树，不是磁盘上的文件。
2. 在 **Styles** 面板里找到 `body`，加一条 `background: red;`。页面背景立刻变红，不需要重新加载 HTML。这说明样式规则和 HTML 是分开解析的。
3. 切到 **Network** 面板，勾选 `Disable cache`，刷新。看 `index.html`、`style.css` 各自返回的状态码是不是 200。

```text
改 DOM 文本 -> 页面立刻变，刷新恢复   => DOM 在内存里
加 CSS 规则 -> 不用重载 HTML 就生效   => CSS 与 HTML 分离
禁用缓存刷新 -> 文件重新下载          => 你看到的不一定是服务器最新版
```

预期：三条现象都能复现。它们分别证明了「DOM 是运行时结构」「渲染靠样式规则」「缓存会骗你」。

## 5. 自测（先别翻答案）

1. 你改了 `style.css` 并保存，刷新线上网址却还是旧样式。最可能的原因是什么？
2. 如果把 `index.html` 里的图片路径从 `assets/me.jpg` 改成 `C:\Users\你\图片\me.jpg`，本地可能能看，线上会怎样？为什么？
3. AI 这次选了 flex。如果换成 grid，哪些结论仍然成立、哪些会变？

答案：
答案：线上托管的是 `dist/` 构建产物，你改的是源码，需要重新 `npm run build` 并重新部署。
答案：线上会裂图。绝对路径指向你本机磁盘，服务器上没有这个文件；浏览器只能请求 URL 路径。
答案：CSS 盒模型、构建产物、静态托管这些结论不变；变的是具体的布局算法和 AI 替你做的那个「选 flex」的决定。

## 6. 换场景会怎样

这套「源码 → 构建 → 静态托管」的原理，一旦页面需要后端就会翻车。
比如你想在主页上放一个「留言板」，把留言存下来：静态托管没有数据库，前端也无法安全地保存写权限，必须再加一个后端服务和数据库。
另一个边界是：如果页面依赖某个第三方接口的 key，把它写进前端等于公开。正确做法是让后端代理请求，key 只存在服务器环境变量里。

## 7. 费曼输出

讲给一个完全不懂技术的朋友听，可以这么说：

> 「AI 帮我写的是几份文本文件。浏览器会把 HTML 变成一棵可以改的树，用 CSS 决定每个盒子多大、放哪儿，再画到屏幕上。我改完文件后还要经过一次打包，最后把打包结果放到一台只会发文件的服务器上，所以别人打开网址就能看到。也正因为服务器只发文件，密码类的东西不能放在页面里。」

如果你能用自己的话讲出这三句，并且能回答「为什么改了没生效」，这张卡就可以打 4 分以上。
